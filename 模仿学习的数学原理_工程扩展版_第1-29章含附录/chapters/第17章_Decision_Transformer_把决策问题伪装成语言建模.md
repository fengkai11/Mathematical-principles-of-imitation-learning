# 第17章：序列策略模型：从 Decision Transformer 到 Transformer Policy

> **本章位置**：本章属于 **第五篇：从历史上下文到多模态条件策略**。第四篇已经回答“动作如何生成”，本章开始回答“动作预测时，条件信息如何组织”。

> **本章一句话导读**：序列策略模型的核心不是“用了 Transformer”，而是把策略的条件变量从当前观测 $o_t$ 扩展为历史、目标、任务阶段和多模态 token 共同组成的上下文 $c_t$。

前面几章已经建立了现代机器人策略的动作建模主线：ACT 预测动作块，Diffusion Policy 从噪声中生成动作块，Flow Matching 用连续速度场生成动作块。它们主要回答一个问题：

```text
动作输出本身应该怎样建模？
```

但机器人策略还需要回答另一个同样重要的问题：

```text
模型在预测动作时，到底应该看见哪些条件？
```

只看当前图像，很多时候是不够的。机械臂插入治具时，当前画面可能看起来差不多，但控制含义完全不同：它可能是刚刚接近治具，也可能是第一次插入失败后正在恢复；可能已经发生过接触，也可能还没接触；可能目标是快速完成，也可能目标是低冲击、低风险完成。

因此，本章的主角不是某个网络名字，而是一个新的数学对象：

```text
上下文 c_t
```

Decision Transformer 是这个思想的典型例子：它把 return-to-go、状态和动作历史组织成序列，在目标回报条件下预测下一步动作。Transformer Policy 则是更一般的形式：图像、语言、状态、历史动作、任务阶段和目标条件都可以变成 token，被统一放入上下文中。

---

## 0. 本章要解决的核心问题

本章要解决的问题是：

> 如何把策略从“当前观测到当前动作”的函数，推广为“上下文到动作”的条件序列模型？

这个问题可以分成三层。

第一层是数学对象升级：

```text
当前观测 o_t
→ 上下文 c_t
```

第二层是训练目标不变：

```text
仍然是在数据轨迹上预测专家动作
```

第三层是工程风险变化：

```text
上下文更长，不等于闭环更安全
```

本章会反复强调这一点：Decision Transformer 和 Transformer Policy 并没有自动消灭模仿学习中的分布偏移。它们只是让策略有机会使用更丰富的条件信息。

---

## 1. 统一贯穿例子：治具插入中的“同图不同义”

考虑一个机械臂把零件插入治具的任务。

在某个时刻，摄像头看到的局部图像非常相似：零件已经靠近孔位，夹爪位置也差不多。可是仅凭当前图像，模型未必知道下面这些信息：

- 这是第一次靠近，还是失败恢复后的第二次靠近；
- 刚才是否发生过侧向接触；
- 上一步动作是向左纠偏，还是向右纠偏；
- 当前任务要求快速插入，还是低接触力插入；
- 语言或任务 ID 是否指定了不同零件或不同孔位。

如果策略只写成 $\pi_\theta(a_t\mid o_t)$，这些信息会被压进当前观测里。当前观测能恢复出来就能用，恢复不出来就会丢失。

序列策略模型的想法是：不要假装当前观测包含一切，而是把历史观测、历史动作和任务条件显式放进上下文中。

## 2. 本章公式主线

本章公式主线可以概括为：

```text
单步策略
→ 上下文条件策略
→ 历史上下文
→ return-to-go 条件
→ Decision Transformer 动作预测
→ 扩展上下文上的条件 BC
→ Transformer Policy 的一般 token 条件
→ attention 聚合上下文
→ 长序列边界与 SSM / Mamba 补充
```

其中最关键的对象是 $c_t$。本章所有公式都围绕它展开。

## 3. 新数学对象定义

**定义 17.1：上下文**

上下文 $c_t$ 指时刻 $t$ 预测动作时，策略允许使用的全部条件信息。它可以包含当前观测、历史观测、历史动作、目标位姿、语言指令、任务阶段、return-to-go 或其他任务条件。

上下文不是一个固定格式的数据结构，而是一个抽象接口。它回答的问题是：

```text
模型在预测 a_t 之前，已经知道了什么？
```

**定义 17.2：上下文条件策略**

上下文条件策略指根据 $c_t$ 预测当前动作或当前动作分布的策略。

**公式 (17.1)：上下文条件策略**

$$\pi_\theta(a_t\mid c_t)$$

这个公式是本章的核心升级。第2章的 BC 主要把条件写成状态或观测；本章把条件统一写成上下文。

如果动作输出不是单步动作，而是第4章定义过的动作块，也可以沿用第4章的动作块策略写法 $\pi_\theta(A_t\mid c_t)$。这里不重新编号，因为动作块已经是前文对象。

**定义 17.3：历史上下文**

历史上下文指由最近一段观测、动作和任务条件构成的上下文。

**公式 (17.2)：有限历史上下文**

$$c_t=(o_{t-K+1:t},a_{t-K+1:t-1},g)$$

其中，$K$ 是历史窗口长度，$g$ 是任务条件。任务条件可以是目标位姿、语言指令、任务 ID、期望回报或人工指定的轨迹质量等级。

这个公式要表达的不是“所有序列策略都必须这么写”，而是说明上下文至少可以显式包含三类信息：

```text
过去看见了什么；
过去做过什么；
当前任务要求什么。
```

**定义 17.4：return-to-go**

return-to-go 记为 $G_t$，表示从当前时刻到轨迹结束还能获得的累计回报或累计进展信号。

**公式 (17.3)：return-to-go**

$$G_t=\sum_{k=t}^{T}r_k$$

如果使用折扣回报，也可以把每一项乘上折扣因子。但本章只保留不折扣形式，避免把重点从上下文建模转移到强化学习细节上。

在机器人模仿学习中，$r_t$ 不一定是严格的环境 reward。它可以是成功进度、人工评分、轨迹质量标签或任务阶段分数。因此，$G_t$ 在 Decision Transformer 中更适合理解为“目标质量条件”，而不是万能的强化学习信号。

**定义 17.5：token 序列**

token 序列 $z_{1:m}$ 指输入 Transformer 的统一序列表示。图像 patch、本体状态、历史动作、语言词元、目标位姿、return-to-go 和任务阶段都可以被编码成 token。

**定义 17.6：Transformer Policy**

Transformer Policy 指用 Transformer 作为上下文建模器，把一组 token 聚合成用于动作预测的表示，并输出动作、动作块或动作 token 分布的策略模型。

## 4. 从单步 BC 到上下文条件 BC

先回到最朴素的 BC。第2章已经给出概率 BC 的负对数似然目标，本章不重复推导。这里只看它的条件变量：

```text
普通 BC：给定当前状态或观测，预测当前动作。
```

序列策略没有改变“用数据动作监督模型”的基本事实。它改变的是条件变量：

```text
上下文条件 BC：给定上下文，预测当前动作。
```

这就是为什么本章仍然属于模仿学习主线，而不是突然跳到一个完全不同的问题。只要训练信号仍然来自数据轨迹中的动作，训练形式就仍然是条件动作预测。

区别在于，模型现在拟合的是：

```text
数据中“在类似上下文下通常采取什么动作”
```

而不是只拟合：

```text
数据中“在类似当前观测下通常采取什么动作”
```

这个变化看似很小，但会改变数据构造、batch 采样、模型结构、部署输入和失败模式。

---

## 5. Decision Transformer：把目标回报放进上下文

Decision Transformer 的核心启发是：

> 不先学习 value function，也不做 Bellman backup，而是把离线轨迹整理成序列，在目标回报和历史条件下预测动作。

一条带奖励轨迹可以写成：

```text
(s_1, a_1, r_1, s_2, a_2, r_2, ..., s_T, a_T, r_T)
```

训练时，可以从这条轨迹中计算每个时刻的 $G_t$。然后把 return-to-go、状态和动作组织成类似语言序列的形式。

**公式 (17.4)：Decision Transformer 输入序列**

$$x_{1:3T}=(G_1,s_1,a_1,G_2,s_2,a_2,\dots,G_T,s_T,a_T)$$

这个序列里，每个时刻有三类 token：

```text
目标条件 token：G_t
状态 token：s_t
动作 token：a_t
```

模型预测 $a_t$ 时，应该能看见到当前时刻为止的目标回报、状态历史和动作历史，但不能偷看未来动作。因此动作预测分布写成：

**公式 (17.5)：Decision Transformer 的动作预测分布**

$$p_\theta(a_t\mid G_{1:t},s_{1:t},a_{1:t-1})$$

这个公式就是 Decision Transformer 和普通 BC 的关键差别。普通 BC 的条件变量通常是 $s_t$ 或 $o_t$，而这里的条件变量变成了更长的历史上下文。

---

## 6. 命题 17.1：Decision Transformer 是扩展上下文上的条件 BC

> **命题 17.1：Decision Transformer 的监督学习视角**
>
> 如果把上下文定义为 $c_t^{DT}=(G_{1:t},s_{1:t},a_{1:t-1})$，那么 Decision Transformer 的动作预测训练可以看成扩展上下文上的条件行为克隆。

**证明**

第一步，普通 BC 的核心监督信号是数据动作。第2章已经说明，BC 通过最小化动作预测误差或负对数似然来拟合数据中的条件动作分布。

第二步，Decision Transformer 仍然用数据中的动作 $a_t$ 作为监督标签。它没有要求模型通过在线探索重新发现动作，也没有要求模型执行 Bellman backup。

第三步，Decision Transformer 只是把条件变量从 $s_t$ 扩展为：

```text
(G_{1:t}, s_{1:t}, a_{1:t-1})
```

因此可以写成统一的条件 BC 目标。

**公式 (17.6)：扩展上下文上的条件 BC 目标**

$$\mathcal{L}_{DT}(\theta)=-\mathbb{E}_{(c_t^{DT},a_t)\sim\mathcal{D}}[\log p_\theta(a_t\mid c_t^{DT})]$$

其中，$c_t^{DT}$ 表示 Decision Transformer 使用的扩展上下文。

连续动作时，公式 (17.6) 可以落到第2章和第5章已经讨论过的 MSE 或高斯 NLL；离散动作 token 时，可以落到交叉熵。这里不重新编号这些目标，因为它们的数学来源已经在前文出现过。

这个命题的意义是：Decision Transformer 不是“Transformer 版万能强化学习”。它更准确的定位是：

```text
目标回报条件下的离线序列动作预测。
```

因此，它仍然依赖数据覆盖。如果数据里没有高质量轨迹，推理时把目标 $G_t$ 设得很高，并不会凭空生成可靠策略。

## 7. 推理时 return-to-go 怎么用

训练时，$G_t$ 来自数据轨迹，可以从后往前计算。

推理时，未来还没发生，真实的 $G_t$ 不可知。常见做法是人为设置一个目标回报或目标质量条件，然后随着执行过程更新剩余目标。

例如，如果每一步能获得进展分数 $r_t$，可以直观更新为：

```text
新的剩余目标 = 旧的剩余目标 - 当前获得的进展
```

这里不把它编号为核心公式，因为本章重点不是回报更新算法，而是说明：return-to-go 在推理时是一个条件输入，而不是未来事实。

在机器人任务中，这一点尤其重要。很多模仿学习数据没有严格 reward，只有成功/失败、阶段标签或人工评分。此时 $G_t$ 更像“轨迹质量提示词”，而不是严格强化学习意义上的价值目标。

## 8. Transformer Policy：从 DT 扩展到一般策略骨架

Decision Transformer 是一个清晰例子，但它不是序列策略模型的全部。更一般地，Transformer Policy 可以把不同来源的信息都转成 token。

**公式 (17.7)：Transformer Policy 的一般 token 条件**

$$\pi_\theta(a_t\mid z_{1:m})$$

其中，$z_{1:m}$ 是输入 token 序列。它可以包含：

```text
图像 patch token；
机器人本体状态 token；
历史动作 token；
语言指令 token；
目标位姿 token；
任务阶段 token；
return-to-go token。
```

这时，Transformer 的关键作用不是“让策略变高级”，而是提供一个统一接口：

```text
把多种条件放进同一个上下文；
让动作预测从上下文中读取相关信息。
```

动作头可以有多种形式。

第一种是连续动作回归。模型输出 $\hat a_t=f_\theta(z_{1:m})$，适合低维连续控制，但仍可能遇到第5章讨论过的多峰均值问题。

第二种是动作 token。连续动作先被量化成离散 token，模型预测动作 token 分布。这会自然连接下一章 VLA 中的动作 token 化问题。

第三种是动作块输出。模型根据 token 上下文输出 $A_t$，这与第4章动作块和第10章 ACT 主线相接。

第四种是生成式动作头。Transformer 不直接输出动作，而是作为 Diffusion Policy 或 Flow Matching 的条件编码器，为生成模型提供上下文表示。

因此，第17章不是替代第四篇，而是补上第四篇没有回答的问题：

```text
第四篇：动作怎么生成？
第17章：生成动作时条件怎么组织？
```

## 9. Attention 在策略中的作用：不是魔法，是条件读取

很多工程讨论会把 attention 说得像魔法，好像模型只要加了 attention，就会自动理解任务。更准确地说，attention 只是提供了一种信息读取机制：

```text
当前 token 根据相似度，从其他 token 中读取信息。
```

如果用矩阵写，缩放点积 attention 可以表示为：

**公式 (17.8)：attention 的上下文读取**

$$\alpha=\text{softmax}\left(\frac{QK^\top}{\sqrt{d}}\right),\quad H=\alpha V$$

其中，$Q$ 表示 query，$K$ 表示 key，$V$ 表示 value，$d$ 是特征维度，$\alpha$ 是注意力权重。

放到机器人策略里，可以这样理解：

```text
query：当前要预测动作时提出的问题；
key：上下文中每个 token 可被匹配的索引；
value：真正被读取的信息内容。
```

例如，当前动作预测需要判断“刚才是否已经发生过侧向接触”。那么动作 query 就应该从历史动作、触觉、本体状态或图像变化 token 中读取相关信息。

但是 attention 只能读取已经进入上下文的信息。没有被编码进 token 的信号，attention 读不到；数据中没有稳定对应关系的模式，attention 也很难可靠利用。

## 10. causal mask：防止训练时偷看未来

在 Decision Transformer 这类自回归策略中，causal mask 很重要。

模型预测 $a_t$ 时，可以看见过去和当前可用条件，但不能看见未来动作。如果训练时允许模型看到完整未来序列，它可能学到的不是“根据当前上下文决策”，而是“从未来答案里复制当前动作”。

这会导致一个危险现象：

```text
离线 loss 很好看，闭环部署很差。
```

因此，自回归动作预测必须保证训练可见信息和部署可见信息一致。凡是部署时不可用的信息，训练时也不能作为动作预测的条件。

---

## 11. 位置编码、时间编码与模态编码

Attention 本身不知道顺序，也不知道 token 类型。它只看到一组向量。

因此，序列策略通常需要给 token 加上额外编码：

```text
内容编码：这个 token 表示什么；
位置或时间编码：这个 token 出现在什么时刻；
模态编码：这个 token 属于图像、状态、动作还是语言。
```

这在机器人任务中很关键。下面两个过程的 token 内容可能相似，但控制含义完全不同：

```text
先接触失败，再执行恢复动作；
先执行恢复动作，再发生接触失败。
```

如果模型不知道时间顺序，就很难判断任务阶段。如果模型不知道模态类型，就可能把动作 token、状态 token 和语言 token 混在一起理解。

## 12. 长序列边界：上下文越长，不一定越安全

长上下文可以提供更多信息，但代价也会增加。至少有三类边界必须写清楚。

### 12.1 历史窗口有限

实际部署时，策略通常只能保留有限窗口。窗口太短，可能丢失关键历史；窗口太长，推理成本、显存和延迟都会增加。

对于装配、插入、纠偏任务，关键事件可能发生在较早时刻。例如，几秒前的一次轻微接触可能决定当前应该继续推进还是先退回恢复。这个信息如果被窗口截断，模型就只能靠当前观测猜。

### 12.2 训练上下文和部署上下文不一致

训练时，历史动作通常来自数据集；部署时，历史动作来自模型自己。这个差异会形成新的闭环分布偏移。

可以直观写成：

```text
训练上下文：历史来自数据轨迹；
部署上下文：历史来自模型自身执行。
```

这说明序列策略虽然缓解了单帧观测信息不足，但并没有自动解决错误累积。模型前几步的小错误会进入后续上下文，继续影响后面的动作预测。

### 12.3 实时推理约束

机器人策略还要满足控制周期。若控制周期为 $\Delta t$，模型推理耗时为 $t_{infer}$，基本要求是 $t_{infer}<\Delta t$。

标准 attention 的计算量随 token 数增长很快。可以用下面的辅助公式记住这个风险：

**公式 (17.9)：标准 attention 的长度复杂度**

$$\mathcal{C}_{attn}=O(L^2d)$$

其中，$L$ 是 token 数，$d$ 是特征维度。

这不是说不能用长上下文，而是说长上下文必须和任务需求、数据规模、模型大小、控制频率一起设计。

## 13. 命题 17.2：长上下文不是免费午餐

> **命题 17.2：长上下文不是免费午餐**
>
> 增加上下文长度可以增加可用信息，但也会增加计算成本、数据需求、过拟合风险和部署延迟。因此，上下文更长不必然意味着闭环策略更安全。

**证明思路**

第一，长上下文增加了输入维度。模型需要从更多 token 中判断哪些信息真正有用。如果数据量不足，模型可能记住训练轨迹里的偶然相关性。

第二，长上下文增加推理成本。公式 (17.9) 说明，标准 attention 的计算复杂度会随 token 数近似二次增长。

第三，机器人闭环控制有实时性约束。即使长上下文提升离线预测精度，如果推理延迟超过控制周期，也可能让闭环控制更不稳定。

所以，序列策略的正确问题不是：

```text
上下文是不是越长越好？
```

而是：

```text
哪些历史信息对当前动作有因果价值，并且值得为它付出计算代价？
```

## 14. 补充：SSM / Mamba 作为长时域策略骨架

SSM / Mamba 在本书中不单独成章。它们更适合作为本章的补充视角，用来回答：

```text
如果 attention 在长上下文上太重，有没有另一种历史建模方式？
```

基础状态空间递推可以写成：

**公式 (17.10)：递推状态压缩历史**

$$h_t=Ah_{t-1}+Bx_t,\quad y_t=Ch_t$$

其中，$x_t$ 是当前输入，$h_t$ 是压缩后的历史状态，$y_t$ 是用于动作预测的输出表示。

在策略模型中，可以把 $x_t$ 理解为当前观测、动作或多模态 token，把 $h_t$ 理解为对过去历史的压缩记忆。

Mamba 的直觉可以粗略理解为：状态更新不再完全固定，而是根据当前输入选择性地保留、写入和遗忘信息。对于机器人策略，这个直觉很自然：

- 普通运动阶段，很多历史帧可能不重要；
- 接触发生瞬间，历史信息突然变得关键；
- 任务阶段切换时，模型需要更新内部记忆；
- 失败恢复时，过去失败动作可能需要被保留。

但本书只把 SSM / Mamba 作为长序列骨架补充，而不是新的模仿学习主线。原因是：它们主要改变上下文建模方式，不直接改变模仿学习训练目标。

## 15. 适用边界与常见误区

**误区一：Decision Transformer 等于强化学习。**

不准确。它可以使用 return-to-go 作为条件，但训练形式仍然是离线轨迹上的动作预测。没有在线探索，也不自动具备 Bellman backup 的纠错能力。

**误区二：Transformer Policy 一定比普通 BC 安全。**

不一定。它能使用更多条件，但也引入更高数据需求、更大计算成本和更复杂的部署输入。

**误区三：attention 会自动找到关键历史。**

attention 只能在输入 token 中读取信息。关键传感器没有输入、时间对齐错误、模态编码混乱、训练数据覆盖不足时，attention 并不会自动补救。

**误区四：上下文越长越好。**

不一定。过长上下文可能带来延迟、过拟合和无关 token 干扰。工程上更重要的是找到与动作决策真正相关的历史窗口。

## 17. 读完本章，你应该能判断什么？

读完本章后，应该能判断以下问题。

1. 一个任务是否真的需要历史上下文，还是当前观测已经足够。
2. Decision Transformer 中的 return-to-go 是有效目标条件，还是只是数据标签噪声。
3. Transformer Policy 的 token 设计是否把关键条件放进了模型。
4. 训练时可见的信息，在部署时是否同样可见。
5. 长上下文带来的收益是否足以抵消延迟和计算成本。
6. SSM / Mamba 是不是适合作为当前任务的长历史压缩骨架。

## 18. 实践提示

做序列策略实验时，建议先从最小上下文开始，而不是一开始就堆所有模态。

一个实用顺序是：

```text
当前观测
→ 当前观测 + 机器人本体状态
→ 最近 K 帧观测
→ 最近 K 帧观测 + 历史动作
→ 加入任务条件或语言条件
→ 再考虑 return-to-go 或轨迹质量条件
```

每增加一种上下文，都要单独验证它是否带来闭环收益。不要只看离线 loss。

对于机器人部署，还要记录：

```text
控制频率；
模型推理耗时；
上下文缓存大小；
传感器时间同步误差；
历史动作来自专家还是模型；
失败后上下文是否会污染后续动作。
```

## 20. 本章定义索引

**定义 17.1：上下文**

上下文 $c_t$ 指时刻 $t$ 预测动作时，策略允许使用的全部条件信息。

**定义 17.2：上下文条件策略**

上下文条件策略指根据上下文 $c_t$ 预测当前动作或当前动作分布的策略。

**定义 17.3：历史上下文**

历史上下文指由最近一段观测、动作和任务条件组成的上下文。

**定义 17.4：return-to-go**

return-to-go 指从当前时刻到轨迹结束还能获得的累计回报或累计进展信号，记为 $G_t$。

**定义 17.5：token 序列**

token 序列 $z_{1:m}$ 指输入 Transformer 的统一序列表示。

**定义 17.6：Transformer Policy**

Transformer Policy 指用 Transformer 作为上下文建模器，并根据 token 上下文输出动作的策略模型。

**定义 17.7：causal mask**

causal mask 指自回归模型中用于阻止当前预测访问未来 token 的掩码机制。

**定义 17.8：递推状态**

递推状态 $h_t$ 指用固定维度状态压缩历史信息的内部记忆。
