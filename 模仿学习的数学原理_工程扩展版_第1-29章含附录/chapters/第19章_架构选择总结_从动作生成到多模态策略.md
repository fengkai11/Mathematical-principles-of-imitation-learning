# 第19章：架构选择总结：从动作生成到多模态策略

> **新版布局位置**：本章属于 **第五篇：长序列架构与多模态策略**，是第五篇的收束章。本章不引入新的大模型名词，而是把第13章到第18章中的动作建模、长序列建模和多模态策略放到一张工程选型表里。

> **本章一句话导读**：策略架构选型不是追热点，而是根据动作分布、上下文长度、任务条件、控制频率、数据规模和安全边界做取舍。

到这里，读者已经见过很多策略模型：BC、ACT、Diffusion Policy、Flow Matching、Decision Transformer、Transformer Policy、SSM / Mamba 补充视角、VLA。

如果把它们都当成“谁更先进”的排行榜，读者会很容易迷路。本章换一个问题：

> 面对一个真实机器人模仿学习任务，工程师应该怎样判断该用哪类策略架构？

本章的答案是：先不要问模型名字，先问任务结构。

---

## 0. 本章一句话导读

本章建立一个工程判断框架：

```text
动作分布复杂度
+ 上下文长度
+ 任务条件类型
+ 控制频率
+ 数据规模
+ 安全要求
→ 策略架构选择
```

这比简单说“Transformer 比 MLP 强”“Diffusion 比 BC 高级”“VLA 是未来”更可靠。

---

## 1. 先区分两个问题：动作怎么生成，上下文怎么建模

很多策略架构看起来混在一起，是因为它们其实回答的是两个不同问题。

第一个问题是：**动作怎么生成？**

这对应第四篇：

- BC：直接回归或分类动作；
- ACT：一次预测动作块；
- Diffusion Policy：通过去噪生成动作；
- Flow Matching：通过连续流场生成动作。

第二个问题是：**上下文怎么建模？**

这对应第五篇：

- Decision Transformer：把 return、state、action 写成序列；
- Transformer Policy：用 attention 聚合上下文；
- SSM / Mamba：用递推状态压缩长历史；
- VLA：把视觉、语言和动作放进统一条件模型。

因此，一个完整策略通常可以拆成：

**公式 (19.1)：策略架构拆解**

$$\text{Policy} = \text{Context Encoder} + \text{Action Decoder}$$

这里，Context Encoder 负责理解观测、历史、目标和语言；Action Decoder 负责输出动作、动作块、动作 token 或动作分布。

这条拆解非常重要。因为 Transformer、VLA、Diffusion、ACT 不是互斥关系。一个 VLA 可以使用 Transformer 做上下文编码，也可以使用 diffusion head 生成动作块。

---

## 2. 动作生成方法怎么选

先看动作分布。

### 2.1 单峰、低维、短时任务：BC 可以先做 baseline

如果任务动作比较确定，同一个观测附近基本只有一种合理动作，BC 是最应该先做的 baseline。

**公式 (19.2)：BC baseline**

$$\pi_\theta(a_t \mid o_t)$$

适用场景包括：

- 规则工件抓取中的粗定位动作；
- 简单轨迹跟随；
- 动作维度低、歧义小的任务；
- 需要快速建立可运行 baseline 的项目。

但如果同一观测下有多种合理动作，BC 的点估计可能会平均掉动作模式。

### 2.2 需要短时连续性：优先考虑动作块

如果任务要求动作在短时间内平滑连续，例如插入、装配、抓取后移动，可以考虑动作块。

**公式 (19.3)：动作块策略**

$$\pi_\theta(A_t \mid c_t),\quad A_t=(a_t,a_{t+1},\dots,a_{t+H-1})$$

ACT 这类方法的价值在于：它不只问下一步动作，而是让策略表达一小段短期意图。

### 2.3 多模态动作明显：考虑生成式策略

如果同一观测和任务条件下存在多种合理动作，例如左侧绕行、右侧绕行、先旋转再抓、先接触再纠偏，那么生成式策略更合适。

Diffusion Policy 和 Flow Matching 的价值在于，它们不强迫策略输出一个平均动作，而是建模条件动作分布或动作块分布。

**公式 (19.4)：生成式动作策略的目标对象**

$$p_{\mathrm{data}}(A_t \mid c_t)$$

这里的重点不是“扩散很潮”，而是任务是否真的需要表达多模态动作分布。

## 3. 上下文建模方法怎么选

再看上下文。

### 3.1 当前观测足够：不必强行上长序列模型

如果当前观测已经包含足够信息，历史信息很少改变动作判断，那么简单策略可能更可靠。

在工程上，简单模型有三个优点：

- 推理快；
- 调试容易；
- 失败模式更可解释。

### 3.2 任务阶段依赖历史：使用序列策略

如果当前观测不能区分任务阶段，就需要历史上下文。

**公式 (19.5)：历史条件策略**

$$\pi_\theta(a_t \mid o_{1:t}, a_{1:t-1}, g)$$

例如机械臂当前在工件旁边，但仅看图像可能不知道它是“准备抓取”还是“抓取失败后正在恢复”。历史动作和状态能提供任务阶段信息。

### 3.3 长历史且实时约束强：考虑递推状态或窗口裁剪

如果历史很长，标准 attention 可能过重。此时有两条路：

- 裁剪窗口，只保留最近 $K$ 步；
- 使用递推状态压缩历史，例如 RNN、SSM / Mamba 类结构。

**公式 (19.6)：递推历史压缩**

$$h_t = F_\theta(h_{t-1}, x_t)$$

这里，$h_t$ 是历史压缩状态，$x_t$ 是当前输入。

## 4. 多模态任务怎么选

如果任务需要语言或多任务泛化，就进入 VLA 讨论范围。

VLA 适合的问题不是“所有机器人任务”，而是：

- 任务目标可以用语言自然描述；
- 同一环境中存在多个可操作对象；
- 策略需要根据语言切换目标；
- 数据中有足够的视觉、语言、动作配对样本；
- 系统允许较复杂模型，并配有安全外壳。

VLA 的核心策略形式是：

**公式 (19.7)：VLA 策略形式**

$$\pi_\theta(a_t \mid I_{1:t}, q_{1:t}, a_{1:t-1}, l)$$

但如果任务只是固定工件、固定槽位、固定节拍，VLA 未必比传统视觉定位加控制器更划算。

## 5. 一个实用选型表

| 任务特征 | 优先 baseline | 可能升级方向 | 主要风险 |
|---|---|---|---|
| 单峰动作、低维控制 | BC / MLP / CNN policy | 加历史窗口 | 分布偏移 |
| 短时连续动作强 | ACT / action chunk | temporal ensemble | 滞后、动作重叠 |
| 多模态动作明显 | Diffusion Policy / Flow Matching | 条件生成式动作块 | 推理延迟、数据需求 |
| 任务阶段依赖历史 | Transformer Policy | DT / causal policy | 上下文过长、泄漏未来 |
| 长历史且低延迟 | RNN / SSM / Mamba 类骨架 | 与动作头组合 | 表达能力和训练稳定性 |
| 语言指定目标 | VLA | action token / diffusion head | grounding、数据混合、安全 |
| 工业高精度固定任务 | 传统视觉 + 控制 + 小策略增强 | 局部学习策略 | 大模型性价比低 |

这张表不是标准答案，而是工程起点。

真正选型时，还要看数据量、控制频率、硬件算力、可解释性、失败成本和团队调试能力。

## 6. 命题 19.1：更强表达能力不等于更好工程方案

> **命题 19.1：策略表达能力与工程可用性不等价**
>
> 一个策略架构能表达更复杂的条件分布，并不意味着它在某个具体机器人任务中一定更安全、更稳定或更划算。

证明思路如下。

假设策略模型类从简单模型 $\Pi_1$ 扩展到复杂模型 $\Pi_2$，并且 $\Pi_1 \subset \Pi_2$。理论上，$\Pi_2$ 的表达能力更强。

但工程部署评价不只取决于训练误差，还取决于：

**公式 (19.8)：工程部署风险的组成**

$$\mathrm{Risk} = R_{\mathrm{fit}} + R_{\mathrm{ood}} + R_{\mathrm{latency}} + R_{\mathrm{safety}} + R_{\mathrm{debug}}$$

其中，$R_{\mathrm{fit}}$ 是拟合误差，$R_{\mathrm{ood}}$ 是分布外风险，$R_{\mathrm{latency}}$ 是延迟风险，$R_{\mathrm{safety}}$ 是安全风险，$R_{\mathrm{debug}}$ 是调试和维护风险。

复杂模型可能降低 $R_{\mathrm{fit}}$，但同时提高其他风险项。例如大模型推理更慢、失败模式更难解释、数据覆盖不足时更容易产生不可控行为。

因此，工程选型不能只看表达能力，还要看总体风险。

## 7. 第五篇小结

第五篇完成了从动作生成到策略架构的过渡。

第17章说明：策略可以写成条件序列模型。Decision Transformer 是代表例子，Transformer Policy 是一般化框架，SSM / Mamba 是长序列补充骨架。

第18章说明：当条件进一步扩展到视觉、语言、本体状态和历史动作时，就进入 VLA。VLA 的核心仍然是条件动作分布学习。

本章进一步收束：策略架构不是越大越好，而是要匹配任务结构。

最重要的工程判断是：

```text
先用简单 baseline 证明任务可学；
再根据失败模式决定升级方向；
不要为了模型名词而升级模型。
```

---

## 本章公式主线

```text
Policy = Context Encoder + Action Decoder
→ 动作生成方法选择：BC / ACT / Diffusion / Flow
→ 上下文建模方法选择：当前观测 / 历史窗口 / Transformer / SSM
→ 多模态条件建模：VLA
→ 工程风险不只包含拟合误差
```

---

## 读完本章，你应该能判断什么？

第一，BC、ACT、Diffusion、Flow 主要回答动作如何生成；Decision Transformer、Transformer Policy、SSM / Mamba、VLA 主要回答上下文如何组织。

第二，VLA 可以和动作块、动作 token、Diffusion 或 Flow 组合，不是和它们互斥。

第三，如果当前观测已经足够，不必为了“高级”强行使用长序列模型。

第四，如果任务没有语言切换目标的需求，VLA 可能不是性价比最高的方案。

第五，工程选型应从失败模式出发，而不是从模型热度出发。
