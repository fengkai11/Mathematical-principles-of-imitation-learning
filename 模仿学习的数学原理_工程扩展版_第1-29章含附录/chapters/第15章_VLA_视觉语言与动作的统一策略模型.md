# 第15章：VLA：视觉、语言与动作的统一策略模型

> **本章位置**：本章属于 **第五篇：从历史上下文到多模态条件策略**。第14章已经把策略从“当前观测到动作”推广为“上下文到动作”，本章继续把上下文扩展为视觉、语言、本体状态和历史动作共同组成的多模态条件。

> **本章一句话导读**：VLA 不是“把大语言模型接到机械臂上”，而是把视觉、语言、机器人状态和历史动作组织成统一上下文，并在这个上下文条件下学习可执行动作分布。

第14章的主角是上下文 $c_t$。它回答的是：

```text
模型预测动作之前，允许知道什么？
```

本章继续推进一步：如果上下文里不只有历史观测和历史动作，还包括图像、语言指令、机器人本体状态、任务阶段和目标对象，策略该怎样写？

这就是 VLA，也就是 Vision-Language-Action 模型要解决的问题。

VLA 这个名字容易让人误解，好像它的关键是“模型会说话”。但对机器人策略来说，语言本身不是最终目标。真正的问题是：

```text
看到了什么？
任务要求什么？
机器人当前状态如何？
过去做过什么？
接下来应该输出什么动作？
```

---

## 0. 本章要解决的问题

本章要解决三个问题。

第一，如何把视觉、语言、本体状态和历史动作统一写成策略条件。

第二，VLA 的动作输出到底可以是连续动作、动作 token、动作块，还是生成式动作头。

第三，为什么 VLA 仍然是条件模仿学习的一种扩展，而不是自动解决分布偏移和安全问题的万能模型。

---

## 1. 从第14章到第15章：上下文继续扩展

第14章的上下文条件策略写成：

```text
pi_theta(a_t | c_t)
```

本章把 $c_t$ 具体化为多模态上下文。

**公式 (15.1)：VLA 多模态上下文**

$$c_t^{VLA}=(I_{1:t},q_{1:t},a_{1:t-1},l)$$

其中，$I_{1:t}$ 表示视觉历史，$q_{1:t}$ 表示机器人本体状态历史，$a_{1:t-1}$ 表示历史动作，$l$ 表示语言指令或任务描述。

于是 VLA 条件策略可以写成：

**公式 (15.2)：VLA 条件策略**

$$\pi_\theta(a_t\mid c_t^{VLA})$$

展开后就是：

**公式 (15.3)：展开形式的 VLA 条件策略**

$$\pi_\theta(a_t\mid I_{1:t},q_{1:t},a_{1:t-1},l)$$

这个公式说明：VLA 的关键不是“语言模型很大”，而是策略条件变量已经从单一观测扩展为多模态上下文。

## 2. 统一贯穿例子：语言指定目标的插入任务

假设机器人面对一个装配台，上面有两个零件和两个孔位。人类给出指令：

```text
把左侧蓝色零件插入右侧圆孔。
```

仅靠当前图像，模型也许能看到零件和孔位；但要正确执行任务，还需要理解：

- 哪个零件是“蓝色零件”；
- 哪个孔位是“右侧圆孔”；
- 当前夹爪是否已经抓住目标；
- 过去是否已经尝试过插入；
- 当前接触状态是否异常；
- 接下来应该输出单步动作、动作块还是高层动作 token。

这就是 VLA 的上下文组织问题。

## 3. 新数学对象定义

**定义 15.1：VLA 多模态上下文**

VLA 多模态上下文是视觉、语言、本体状态、历史动作和任务条件组成的统一策略条件。

**定义 15.2：视觉 token**

视觉 token 是由图像、视频帧、patch、目标区域或视觉 backbone 输出的表示，用于描述机器人看到的环境。

**定义 15.3：语言 token**

语言 token 是由任务指令、目标描述、约束条件或人类反馈编码得到的表示，用于描述机器人应该完成什么。

**定义 15.4：动作 token**

动作 token 是把连续动作、动作块或离散技能编码成 token 后得到的动作表示。它可以用于离散预测，也可以作为动作解码器的中间表示。

**定义 15.5：Action Decoder**

Action Decoder 是把多模态融合表示解码成具体动作、动作块、动作 token 或生成式动作分布的模块。

---

## 4. VLA 标准网络框架

一个 VLA 系统通常包含三部分。

```text
多模态编码器：把视觉、语言、状态、历史动作编码成 token；
融合骨干网络：在 token 序列上建模上下文关系；
动作解码器：输出动作、动作块、动作 token 或生成式动作分布。
```

视觉编码可以写成：

**公式 (15.4)：视觉编码**

$$v_{1:n}=E_v(I_{1:t})$$

语言编码可以写成：

**公式 (15.5)：语言编码**

$$u_{1:m}=E_l(l)$$

机器人状态和历史动作也可以编码成 token。

**公式 (15.6)：状态与历史动作编码**

$$r_{1:t}=E_q(q_{1:t}),\quad b_{1:t-1}=E_a(a_{1:t-1})$$

把这些 token 拼接起来，就得到多模态 token 序列。

**公式 (15.7)：多模态 token 序列**

$$z_{1:M}=[v_{1:n},u_{1:m},r_{1:t},b_{1:t-1}]$$

融合网络把 token 序列变成用于动作预测的上下文表示。

**公式 (15.8)：多模态融合表示**

$$h_t=F_\theta(z_{1:M})$$

动作解码器再根据 $h_t$ 输出动作。

## 5. 动作输出：连续动作、动作 token、动作块与生成式动作头

VLA 的动作输出不只有一种形式。

第一种是连续动作回归。

**公式 (15.9)：连续动作解码**

$$\hat a_t=D_\theta(h_t)$$

这种方式简单直接，但容易遇到第5章讨论过的多峰均值问题。

第二种是动作 token 预测。

**公式 (15.10)：动作 token 条件分布**

$$p_\theta(y_t\mid h_t)$$

其中，$y_t$ 是离散动作 token。动作 token 适合把连续控制问题转成序列预测问题，但需要设计量化方式和解码方式。

第三种是动作块策略。

**公式 (15.11)：VLA 动作块策略**

$$\pi_\theta(A_t\mid h_t)$$

这条公式直接连接第4章的动作块、第10章 ACT、第11章 Diffusion Policy 和第12章 Flow Matching。

第四种是生成式动作头。此时 VLA 不直接输出最终动作，而是为 Diffusion 或 Flow 提供条件表示 $h_t$。

## 6. 命题 15.1：VLA 是多模态上下文上的条件 BC

> **命题 15.1：VLA 的监督学习视角**
>
> 如果训练数据由多模态上下文和专家动作组成，那么 VLA 的监督训练可以看成多模态上下文上的条件行为克隆。

**证明**

第一步，普通 BC 的训练样本是状态或观测与专家动作对。

第二步，VLA 只是把条件变量从单一观测扩展为多模态上下文 $c_t^{VLA}$。

第三步，只要监督信号仍然是数据中的专家动作，训练目标仍然可以写成条件动作预测。

**公式 (15.12)：VLA 监督学习目标**

$$L_{VLA}(\theta)=-\mathbb{E}_{(c_t^{VLA},a_t)\sim D}[\log p_\theta(a_t\mid c_t^{VLA})]$$

因此，VLA 没有自动摆脱模仿学习的数据覆盖问题。它只是让策略可以依赖更丰富的上下文。

---

## 7. VLA 与第四篇动作生成模型的关系

第四篇讨论的是动作分布如何生成。

```text
ACT：隐变量动作块生成；
Diffusion Policy：从噪声中逐步去噪生成动作块；
Flow Matching：沿连续速度场生成动作块。
```

本章讨论的是动作生成之前的条件表示。

```text
VLA：把视觉、语言、状态、历史动作编码成动作生成所需的上下文 h_t。
```

因此，VLA 和生成式动作策略不是替代关系，而是组合关系。

```text
VLA / 多模态编码器提供 h_t；
ACT / Diffusion / Flow 根据 h_t 生成动作或动作块。
```

## 8. VLA 的工程边界

VLA 的表达能力很强，但边界必须说清楚。

第一，语言理解不等于动作可靠。模型能理解“把杯子放到架子上”，不代表它能稳定抓取、避障和放置。

第二，多模态上下文不等于数据覆盖。训练数据没有覆盖的失败恢复、遮挡、夹具变形、异常接触，VLA 仍然可能失败。

第三，模型越大，实时性、部署成本和调试成本越高。机器人策略不是离线问答系统，它要满足控制频率和安全约束。

第四，动作输出必须和底层控制接口匹配。VLA 输出的 token、动作块或连续动作，都要能落到底层控制器。

---

## 9. 策略架构拆解：Context Encoder 与 Action Decoder

为了避免把 VLA 理解成一个黑箱，可以把策略拆成两部分。

**公式 (15.13)：策略架构拆解**

$$\pi_\theta=\psi_\theta\circ\phi_\theta$$

其中，$\phi_\theta$ 是 Context Encoder，负责把视觉、语言、状态和历史动作编码成上下文表示；$\psi_\theta$ 是 Action Decoder，负责把上下文表示解码成动作。

这个拆解很重要，因为工程上常见的差异不一定在“大模型”本身，而在：

```text
上下文编码器是否能理解任务；
动作解码器是否适合机器人控制；
两者是否能在真实闭环中稳定配合。
```

---

## 10. 部署风险：表达能力不等于工程可用性

VLA 的部署风险可以粗略拆成几类。

**公式 (15.14)：部署风险分解**

$$R_{deploy}=R_{fit}+R_{ood}+R_{latency}+R_{safety}+R_{debug}$$

其中，$R_{fit}$ 表示拟合误差，$R_{ood}$ 表示分布外风险，$R_{latency}$ 表示延迟风险，$R_{safety}$ 表示安全风险，$R_{debug}$ 表示调试和可解释性成本。

这个公式不是严格定理，而是工程检查清单。它提醒我们：VLA 的表达能力越强，不代表部署风险越低。

---

## 11. 读完本章，你应该能判断什么

读完本章后，你应该能判断：

1. VLA 的核心是多模态上下文条件策略，而不是“会说话的机器人”。
2. VLA 条件策略可以写成 $\pi_\theta(a_t\mid c_t^{VLA})$。
3. 多模态 token 序列把视觉、语言、状态和历史动作统一到一个上下文接口里。
4. VLA 的动作输出可以是连续动作、动作 token、动作块或生成式动作头。
5. VLA 仍然是条件模仿学习，仍然依赖数据覆盖。
6. VLA 可以和 ACT、Diffusion Policy、Flow Matching 组合，而不是替代它们。
7. 工程部署要同时检查拟合、OOD、延迟、安全和调试成本。
