# 第23章：快慢模型：通用机器人为什么需要双系统架构

> **本章一句话导读**：本章用时间尺度和控制频率解释快慢模型，说明慢模型负责理解、预测和规划，快模型负责低延迟、连续、稳定地执行动作。

---

## 0. 本章要解决的问题

前面几章已经把现代机器人策略的主要技术拼图展开了：

- 第13章 ACT 说明了为什么机器人可以一次预测一小段动作；
- 第14章 Diffusion Policy 说明了为什么复杂动作分布需要生成式策略；
- 第15章 Flow Matching 说明了动作生成也可以写成连续流场；
- 第17章序列策略模型说明了历史上下文如何进入策略；
- 第18章 VLA 说明了视觉、语言和动作可以进入统一条件策略；
- 第22章 World Models / WAM / JEPA 说明了机器人不能只看当前输入，还要预测未来世界。

但是，这里还缺一个非常重要的架构问题：

> 一个通用机器人系统，能不能只靠一个大模型从图像和语言直接输出所有高频控制动作？

直觉上，这很诱人。

**公式 (23.1)：端到端动作映射**

$$(o_t,q) \longrightarrow a_t$$

其中，$o_t$ 是当前观测，$q$ 是语言指令，$a_t$ 是动作。

但在真实机器人系统中，这种“一口气端到端”的方案很快会遇到三个问题：

1. **慢推理问题**：大 VLM / VLA 擅长语义理解，但推理延迟通常较高；
2. **高频控制问题**：机械臂、灵巧手、双臂协调需要稳定、低延迟、连续动作；
3. **层级抽象问题**：任务理解、子目标规划、世界预测和动作控制不应该都压在同一个时间尺度上。

快慢模型要解决的正是这个问题。

本章的核心观点是：

> 通用机器人策略很可能不是一个单一频率、单一模块的端到端模型，而是由“慢模型”和“快模型”组成的双系统架构。

---

## 1. 本章公式主线

快慢模型的核心不是模型数量，而是时间尺度分工。

先定义慢周期和快周期之间的关系。

**公式 (23.2)：快慢时间尺度关系**

$$t \in \{kM,kM+1,\dots,(k+1)M-1\}$$

其中，$k$ 是慢时间尺度，$t$ 是快时间尺度，$M$ 表示一个慢模型决策周期覆盖多少个快控制步。

慢模型生成高层条件：

**公式 (23.3)：慢模型抽象意图**

$$z_k=g_\phi(o_{\le kM},q)$$

快模型在高层条件下输出动作：

**公式 (23.4)：快模型单步策略**

$$a_t \sim \pi_\theta(a_t \mid o_{t-L:t},z_k)$$

如果快模型一次输出动作块：

**公式 (23.5)：快模型动作块策略**

$$A_t \sim \pi_\theta(A_t \mid o_{t-L:t},z_k)$$

真实系统中，慢模型和快模型往往异步执行，因此快模型使用最近一次可用的慢模型条件：

**公式 (23.6)：异步条件缓存**

$$\bar z_t=z_{\kappa(t)}$$

实际执行时，快模型使用缓存条件：

**公式 (23.7)：异步快策略**

$$a_t \sim \pi_\theta(a_t \mid o_{t-L:t},\bar z_t)$$

这条公式链说明：第23章不是在讲“两个模型拼起来”，而是在讲“慢速理解与快速控制如何通过条件变量连接起来”。

## 2. 一个直观场景：让机器人收拾桌面

假设机器人接收到指令：

> 把桌子上的杯子放到水槽旁边，顺手把抹布叠好。

这个任务至少包含两类能力。

第一类是慢能力：

- 理解“杯子”“水槽”“抹布”分别是什么；
- 判断哪个物体先处理；
- 规划大致步骤；
- 发现杯子里可能有水；
- 预测抓取后物体会怎么运动；
- 决定失败时是否重试或换策略。

第二类是快能力：

- 手臂运动要平滑；
- 夹爪闭合要及时；
- 接触力不能过大；
- 抓杯子时要实时补偿偏差；
- 抹布折叠时要连续控制末端轨迹。

如果让同一个大模型在每个控制周期都重新理解语言、看图、推理、规划、输出关节命令，系统会非常慢；如果只用一个高频动作模型，它又可能不知道“为什么要这么做”。

因此更合理的结构是：

```text
慢模型：理解任务、预测世界、给出子目标或动作意图
快模型：在短时间内把子目标转成连续动作并闭环执行
```

## 3. 快慢模型的数学抽象

我们把机器人系统拆成两个时间尺度。

慢时间尺度记为 $k$，快时间尺度记为 $t$。通常一个慢周期会覆盖多个快控制周期，即公式 (23.2)：

$$t \in \{kM,kM+1,\dots,(k+1)M-1\}$$

其中，$M$ 表示一个慢模型决策周期内包含多少个快控制步。

### 3.1 慢模型：从观测历史和指令生成抽象意图

慢模型可以写成公式 (23.3)：

$$z_k=g_\phi(o_{\le kM},q)$$

其中：

- $o_{\le kM}$：到当前慢周期为止的观测历史；
- $q$：语言指令或任务描述；
- $g_\phi$：慢模型，可以是 VLM、VLA、高层 planner、world model 或价值模型；
- $z_k$：慢模型输出的抽象表示，可以是子目标、计划、latent instruction、goal image 或动作意图。

这个式子的含义不是“慢模型直接控制电机”，而是：

> 慢模型负责把复杂任务压缩成一段可执行的高层条件。

### 3.2 快模型：在高层条件下输出连续动作

快模型可以写成公式 (23.4)：

$$a_t \sim \pi_\theta(a_t \mid o_{t-L:t},z_k)$$

其中：

- $o_{t-L:t}$：最近一段短历史观测；
- $z_k$：慢模型给出的当前高层条件；
- $\pi_\theta$：快动作策略；
- $a_t$：快控制周期下的动作。

如果快模型一次输出动作块，可以写成公式 (23.5)：

$$A_t \sim \pi_\theta(A_t \mid o_{t-L:t},z_k)$$

这就把第13章 ACT、第14章 Diffusion Policy、第15章 Flow Matching 都纳入同一个框架：

- ACT：$\pi_\theta$ 通过 action chunk 直接输出 $A_t$；
- Diffusion Policy：$\pi_\theta$ 通过反向去噪生成 $A_t$；
- Flow Matching：$\pi_\theta$ 通过速度场积分生成 $A_t$。

## 4. 频率约束：为什么必须区分快和慢

快慢模型不是为了好听，而是由控制频率约束逼出来的。

假设快控制周期是：

**公式 (23.8)：快控制周期**

$$\Delta t_{\mathrm{fast}}=\frac{1}{f_{\mathrm{fast}}}$$

慢模型推理耗时为 $T_{\mathrm{slow}}$，快模型推理耗时为 $T_{\mathrm{fast}}$。

如果一个模型要直接参与高频控制，它至少需要满足：

**公式 (23.9)：快模型延迟约束**

$$T_{\mathrm{fast}}<\Delta t_{\mathrm{fast}}$$

但大模型推理通常更适合低频运行：

**公式 (23.10)：慢模型耗时关系**

$$T_{\mathrm{slow}}\gg \Delta t_{\mathrm{fast}}$$

所以系统不能等待慢模型每一步都输出动作，而应该让慢模型低频更新条件 $z_k$，让快模型高频执行。

这就是快慢模型的工程根源：

> 慢模型负责“想清楚”，快模型负责“做得稳”。

## 5. 命题：延迟约束推出快慢分工

> **命题 23.1：高频控制约束下，慢模型不适合逐步输出低层动作**
>
> 如果快控制周期为 $\Delta t_{\mathrm{fast}}$，慢模型单次推理耗时为 $T_{\mathrm{slow}}$，且 $T_{\mathrm{slow}}>\Delta t_{\mathrm{fast}}$，那么慢模型不能在每个快控制周期内同步输出低层动作。

**证明思路**：

快控制要求每个周期都必须在 $\Delta t_{\mathrm{fast}}$ 内得到可执行动作。如果慢模型推理耗时超过这个周期，则动作输出会滞后于控制循环，系统无法形成稳定闭环。

**证明**：

快控制周期为：

$$\Delta t_{\mathrm{fast}}=\frac{1}{f_{\mathrm{fast}}}$$

如果某个模型要每个快周期都输出动作，则它的推理耗时 $T$ 必须满足：

$$T<\Delta t_{\mathrm{fast}}$$

现在慢模型满足：

$$T_{\mathrm{slow}}>\Delta t_{\mathrm{fast}}$$

这与高频控制的实时输出要求矛盾。因此，慢模型不能同步参与每一个快控制周期的低层动作输出。

它更适合低频地产生子目标、计划、风险判断、世界预测结果或 latent condition，再由快模型在高频控制周期内执行。

**这个命题告诉我们什么？**

快慢模型不是拍脑袋分层，而是由控制周期、推理延迟和闭环稳定性共同决定的工程约束。

**常见误解**：

不要把“慢模型能力强”误认为“它可以直接控制一切”。如果推理延迟不满足控制周期，它越聪明也越可能拖慢闭环。

## 6. 异步执行：慢模型不阻塞快控制

真实系统里，慢模型和快模型通常不是严格同步执行，而是异步通信。

可以用一个条件缓存来表示：

$$\bar z_t=z_{\kappa(t)}$$

其中：

- $\kappa(t)$：在快时间 $t$ 时，最近一次已经完成的慢模型决策编号；
- $\bar z_t$：快模型当前可用的高层条件。

于是快模型实际执行的是：

$$a_t \sim \pi_\theta(a_t \mid o_{t-L:t},\bar z_t)$$

这说明：

- 慢模型可以晚一点更新；
- 快模型不能停下来等；
- 如果慢模型还没返回，快模型就使用最近一次有效条件继续执行；
- 当条件过期或风险上升时，系统应该触发 fallback。

## 7. 快模型和慢模型分别对应前文哪些方法

### 7.1 慢模型候选

慢模型可以来自：

- **VLA / VLM**：理解图像、语言和任务语义；
- **World Model / WAM / JEPA**：预测未来隐状态或物理后果；
- **高层 planner**：拆分任务、选择子目标；
- **价值模型 / 偏好模型**：判断哪种计划更安全、更符合人类偏好。

数学上，慢模型经常处理的是抽象状态、目标、计划和未来预测，例如：

**公式 (23.11)：慢模型抽象状态转移**

$$p(z_{k+1} \mid z_k,u_k)$$

或者：

**公式 (23.12)：慢模型高层输出**

$$\hat y_k=h_\phi(o_{\le kM},q)$$

其中，$u_k$ 可以是高层技能、子目标或计划动作，$\hat y_k$ 可以是任务进度、风险、计划或高层条件。

### 7.2 快模型候选

快模型可以来自：

- **BC**：规则任务中直接回归动作；
- **ACT**：输出短 horizon 的动作块；
- **Diffusion Policy**：生成复杂多峰动作块；
- **Flow Matching**：用连续流场生成动作；
- **SSM / Mamba 类策略**：处理长历史但保持较低推理开销；
- **传统控制器 / 轨迹跟踪器**：在明确目标下做稳定执行。

数学上，快模型关注的是：

**公式 (23.13)：高层条件下的快动作块策略**

$$\pi_\theta(A_t \mid o_{t-L:t},z_k)$$

它的重点不是“想清楚任务”，而是“把动作做稳、做快、做连续”。

## 8. 快慢模型与世界模型的关系

第22章讲的世界模型可以自然放到慢模型中。

假设慢模型内部维护一个 latent state：

**公式 (23.14)：慢系统 latent state**

$$h_k=e_\phi(o_{\le kM})$$

并预测候选高层动作 $u_k$ 的后果：

**公式 (23.15)：高层动作后果预测**

$$\hat h_{k+1}=F_\psi(h_k,u_k)$$

那么慢模型可以通过比较不同候选计划的预测结果来选择更好的子目标：

**公式 (23.16)：慢模型计划选择**

$$u_k^*=\arg\max_{u_k}J(\hat h_{k+1},q)$$

这里的 $J$ 可以表示任务进度、安全性、偏好分数或价值估计。

选出的 $u_k^*$ 不一定直接是关节动作，它更可能转化为快模型条件：

**公式 (23.17)：高层计划到快模型条件**

$$z_k=r_\eta(u_k^*,\hat h_{k+1},q)$$

然后快模型负责执行。

## 9. 快慢模型与 DPO / 后训练的关系

后续 Preference Alignment 与 DPO 可以分别作用在快慢两层。

慢模型偏好数据可以是：

**公式 (23.18)：慢模型偏好对**

$$(z_k^+,z_k^-)$$

表示同一个场景下，人类更偏好某个高层计划而不是另一个高层计划。

快模型偏好数据可以是：

**公式 (23.19)：快模型动作偏好对**

$$(A_t^+,A_t^-)$$

表示同一个条件下，人类更偏好某段安全、平滑、成功的动作轨迹，而不是失败、碰撞或不稳定的轨迹。

因此，机器人后训练并不只是在“语言输出”上做偏好对齐，而是可以扩展为：

**公式 (23.20)：机器人偏好数据集**

$$\mathcal{D}_{\mathrm{pref}}=\{(c_i,y_i^+,y_i^-)\}_{i=1}^{N}$$

其中，$c_i$ 可以是场景条件，$y_i$ 可以是高层计划，也可以是低层动作轨迹。

## 10. 工程实现中的典型系统形态

一个实际快慢系统可以写成如下结构：

```text
语言指令 + 图像观测
        ↓
慢模型：VLM / VLA / World Model
        ↓
子目标 / latent intention / goal representation
        ↓
快模型：ACT / Diffusion / Flow / SSM Policy
        ↓
连续动作 / action chunk
        ↓
安全约束 / fallback / controller
        ↓
真实机器人
```

这套结构有一个关键优点：

> 慢模型可以越来越聪明，快模型可以越来越稳，二者不必在同一个频率和同一个模型容量上互相拖累。

## 11. 常见误解与适用边界

| 常见误解 | 正确认识 |
|---|---|
| 快慢模型就是两个模型随便串起来 | 关键不是数量，而是时间尺度、职责边界和通信接口 |
| 慢模型一定是大语言模型 | 慢模型可以是 VLM、VLA、World Model、planner、价值模型或传统任务规划模块 |
| 快模型一定是小模型 | 快模型的核心要求是低延迟和稳定控制，不是参数量一定小 |
| 快慢模型能自动解决安全问题 | 它只是提供架构分工，安全仍需要限幅、碰撞检测、fallback、异常检测和人工接管 |
| 慢模型越聪明越适合直接控制 | 如果延迟不满足控制周期，它就不适合逐步输出低层动作 |

## 12. 回到统一例子

### 12.1 二维点机器人

慢模型可以决定：

- 先绕过障碍物左侧；
- 到达中间 waypoint；
- 再靠近目标点。

快模型负责：

- 在每个短周期输出速度；
- 让轨迹平滑；
- 避免过冲和振荡。

### 12.2 机械臂抓取

慢模型可以决定：

- 先从哪一侧接近物体；
- 抓取哪个部位；
- 是否需要先推开遮挡物；
- 抓取失败后是否换抓取姿态。

快模型负责：

- 末端轨迹跟踪；
- 夹爪闭合时机；
- 接触过程中的微调；
- 把动作块稳定执行到控制器层。

## 13. 读完本章，你应该能判断什么

读完本章后，你应该能判断：

1. 快慢模型不是“两个模型拼接”，而是时间尺度和控制频率驱动的架构分工。
2. 慢模型适合理解任务、预测未来、选择子目标和判断风险。
3. 快模型适合低延迟、连续、稳定地输出动作或动作块。
4. 如果慢模型推理耗时大于快控制周期，它就不适合逐步控制低层动作。
5. 异步条件缓存可以避免慢模型阻塞快控制，但必须配合过期检测、fallback 和安全仲裁。
6. Preference Alignment 和 DPO 不只可以作用在语言输出，也可以作用在高层计划和低层动作轨迹上。

## 17. 本章小结

快慢模型不是一个孤立算法，而是一种组织机器人智能系统的架构原则。

它把全书前面的内容重新串成一条系统链路：

```text
慢模型：VLA / World Model / JEPA / planner
    ↓
高层条件：子目标 / latent intention / goal representation
    ↓
快模型：ACT / Diffusion Policy / Flow Matching / SSM-Mamba
    ↓
动作执行：连续控制 / 安全约束 / fallback
    ↓
后训练：Preference Alignment / DPO / 接管纠偏
```

这也是为什么本章放在 World Models / WAM / JEPA 之后、Preference Alignment / DPO 之前：它一方面承接“机器人要理解和预测世界”，另一方面为“如何后训练和部署一个真正可用的机器人策略系统”搭桥。

## 18. 推荐阅读与深入材料

### 阅读目的

本章要解释为什么通用机器人需要慢系统做理解、规划、反思，快系统做低延迟动作执行。推荐阅读要覆盖认知启发、层级控制和语言 / 策略组合。

### 推荐材料

1. **Kahneman, 2011, “Thinking, Fast and Slow”**
   - 类型：认知启发 / 背景材料。
   - 阅读目的：理解快系统 / 慢系统的直觉来源。
   - 对应本章：只作为类比，不要把心理学结论机械套用到机器人架构。

2. **Sutton, Precup, and Singh, 1999, “Between MDPs and Semi-MDPs: A Framework for Temporal Abstraction in Reinforcement Learning”**
   - 类型：经典 / 层级决策基础。
   - 阅读目的：理解 options、temporal abstraction 和高低层策略。
   - 对应本章：理解为什么长任务需要时间抽象。

3. **Ahn et al., 2022, “Do As I Can, Not As I Say: Grounding Language in Robotic Affordances” / SayCan**
   - 类型：经典 / 机器人认知架构。
   - 阅读目的：理解语言模型给候选计划，机器人 affordance / value 判断可执行性。
   - 对应本章：慢系统提出方案，执行可行性模型筛选方案。

4. **Liang et al., 2023, “Code as Policies”**
   - 类型：前沿 / 语言到控制程序。
   - 阅读目的：理解慢系统如何生成可组合的控制代码。
   - 对应本章：高层语言或程序如何作为快系统条件。

5. **Huang et al., 2022, “Inner Monologue: Embodied Reasoning through Planning with Language Models”**
   - 类型：前沿 / 反馈闭环。
   - 阅读目的：理解语言反馈、环境反馈和重新规划如何结合。
   - 对应本章：慢系统如何利用反馈更新计划。

### 阅读提示

读快慢系统材料时，建议标注每个模块的控制频率：语言规划是秒级还是分钟级？低层控制是 10Hz、50Hz 还是更高？频率错配是工程落地的核心问题。
