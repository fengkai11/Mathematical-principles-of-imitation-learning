# 公式格式说明

> 作用：本文件是全书公式格式的专门规范。若《全书写作指导.md》与本文档冲突，以本文档为准。所有章节修改、公式索引整理、全书公式目录更新，都必须按本文档检查。

---

## 1. 总原则

公式格式优先追求：

```text
GitHub 网页端可读；
mdBook 中尽量稳定；
易读；
少宏；
少嵌套；
少重复编号。
```

当前仓库的 Markdown 经常需要直接在 GitHub 网页端阅读，因此公式写法不能只考虑 mdBook。若 GitHub 网页端和 mdBook 存在冲突，正文优先保证 GitHub 网页端不要显示裸露的 `$$`。

---

## 2. GitHub 网页端优先的块公式格式

重要公式统一采用“标题 + 单行 display math”格式：

```markdown
**公式 (x.y)：公式名称**

$$...$$
```

正确示例：

```markdown
**公式 (13.3)：ACT 的 chunk loss + KL 目标**

$$\mathcal{L}_{ACT}(\theta,\phi)=\mathbb{E}_{z\sim q_\phi(z\mid c_t,A_t)}\left[\mathcal{L}_{chunk}(A_t,\hat A_t)\right]+\beta D_{KL}\left(q_\phi(z\mid c_t,A_t)\Vert p(z)\right)$$
```

要求：

```text
公式标题单独一行；
公式标题和公式之间保留一个空行；
整条公式放在一行 $$...$$ 中；
公式后保留一个空行再写解释；
公式块中不放中文说明。
```

---

## 3. 不推荐的多行 $$ 块公式

在 GitHub 网页端直接阅读时，多行 `$$` 块公式有时会显示成裸露文本，尤其在中文标题、列表、引用块、表格附近更容易暴露问题。

不推荐：

```markdown
**公式 (13.3)：ACT 的 chunk loss + KL 目标**

$$
\mathcal{L}_{ACT}(\theta,\phi)
=
...
$$
```

如果公式太长，优先压缩符号或拆成两个编号公式，而不是写成很长的多行 display math。

---

## 4. 禁止使用的写法

全书公式中禁止使用：

```text
\tag{}
<div class="math">
</div>
<span class="math">
</span>
\operatorname
```

除非已经在本文件中明确允许，否则不要新增复杂 LaTeX 宏。

---

## 5. 下标文字的写法

为了提高 GitHub / mdBook 渲染稳定性，公式下标中的英文说明尽量使用普通字母，不使用 `\mathrm{}`。

推荐写法：

```text
\mathcal{L}_{ACT}
\mathcal{L}_{chunk}
D_{KL}
\mathcal{D}_{chunk}
\mathcal{L}_{smooth}
```

不推荐写法：

```text
\mathcal{L}_{\mathrm{ACT}}
\mathcal{L}_{\mathrm{chunk}}
D_{\mathrm{KL}}
\mathcal{D}_{\mathrm{chunk}}
\mathcal{L}_{\mathrm{smooth}}
```

说明：

```text
\mathrm 本身不是数学上错误，但在本书当前渲染链路中容易造成排查成本。
对于 ACT、KL、chunk、smooth、offline、deploy 等说明性下标，统一用普通下标。
```

---

## 6. 表格中的公式

表格中的公式必须尽量短。

允许：

```markdown
| (13.1) | ACT 条件动作块生成 | $p_\theta(A_t\mid c_t,z)$ | A |
```

不推荐在表格中放长公式，例如：

```markdown
| (13.3) | ACT loss | $\mathcal{L}_{ACT}=\mathbb{E}_{...}[...] + ...$ | A |
```

如果公式较长，公式目录表格中只放公式名称或简写，正文公式索引中再放完整公式。

推荐写法：

```markdown
| (13.3) | ACT 的 chunk loss + KL 目标 | 见第13章公式 (13.3) | A |
```

---

## 7. 行内公式规则

行内公式只放短对象，例如：

```text
$A_t$
$c_t$
$\pi_\theta(A_t\mid c_t)$
$D_{KL}$
```

不要把长训练目标、长期望、长 KL 目标塞进普通正文段落。长公式必须放在“标题 + 单行 display math”格式中。

---

## 8. 公式块检查清单

每次修改章节后，必须检查：

```text
1. GitHub 网页端是否显示裸露的 $$；
2. 是否存在多行 $$ 块公式；
3. 是否存在 \tag{}；
4. 是否存在 <div class="math"> 或 <span class="math">；
5. 是否存在 \operatorname；
6. 是否存在不必要的 \mathrm；
7. 长公式是否被塞进 Markdown 表格；
8. 公式块内是否夹杂中文说明；
9. 是否重复编号已经在前文介绍过的公式；
10. 是否把 C 类推导中间式误当核心公式编号。
```

---

## 9. 修复优先级

发现 GitHub 网页端公式渲染问题时，按以下顺序修复：

```text
1. 先把多行 $$ 公式改成单行 $$...$$；
2. 再删除不必要宏，如 \mathrm、\operatorname；
3. 再把长公式从表格移到正文公式索引；
4. 再检查括号、上下标、\left / \right 是否成对；
5. 最后检查章节正文、公式索引和全书公式目录是否同步。
```
