# 全书写作指导

> 作用：本文件合并第一篇、第二篇改造过程中形成的写作规则，用作后续第三篇到第六篇统一改造标准。后续所有篇章改写、精修、删减、补图、公式整理、目录更新，都优先遵守本文档。若某一篇的局部计划与本文档冲突，以本文档为准；若本文档与《公式格式说明.md》冲突，以《公式格式说明.md》为准。

---

## 1. 本书定位

本书定位为：

> **《模仿学习的数学原理：从行为克隆到 Diffusion Policy》**

本书不是方法罗列，也不是论文综述，而是面向工程师和学习者的数学原理书。

目标读者：

```text
有基础数学知识；
能读懂基本函数、概率、期望、损失函数；
不默认熟悉概率统计推导；
希望理解模仿学习背后的数学对象和公式来源；
希望知道现代机器人策略模型为什么这样设计。
```

核心写作目标：

```text
让读者知道每个方法背后的数学对象是什么；
让读者知道公式为什么出现，而不是只记公式长什么样；
让读者能从 BC、DAgger、IRL、GAIL、ACT、Diffusion Policy、Flow Matching、VLA、World Model 中看见一条连续数学主线。
```

---

## 2. 全书数学主线

全书必须围绕一条主线展开：

```text
专家轨迹
→ 策略
→ 执行分布
→ 分布偏移
→ 动作序列
→ 条件动作分布
→ 隐变量 / 生成式策略
→ occupancy measure / reward / distribution matching
→ 现代动作生成策略
→ 历史上下文与多模态条件策略
→ 世界预测与动作后果建模
```

每一篇都必须回答一个“数学对象升级”问题。

```text
第一篇：从动作拟合到执行分布
第二篇：从单步动作标签到可表达多解的策略模型
第三篇：从动作监督到分布匹配与奖励视角
第四篇：从简单策略到现代动作生成模型
第五篇：从当前观测到历史上下文与多模态条件策略
第六篇：从动作模仿到世界预测与动作后果建模
```

每章只能完成一个主要对象升级。不要一章同时讲多个互不承接的问题。

---

## 3. 每章标准结构

每章推荐采用以下结构：

```text
0. 本章一句话导读
1. 本章要解决的核心问题
2. 统一贯穿例子
3. 新数学对象定义
4. 核心公式
5. 公式来源或台阶式推导
6. 关键命题 / 结论
7. 适用边界与误区
8. 与上一章和下一章的关系
9. 读完本章，你应该能判断什么
10. 实践提示
11. 本章公式索引
12. 本章定义索引
13. 思考题
14. 配图清单
15. 推荐阅读：重点看什么
```

并非每章必须机械拥有所有小节，但每章至少要具备：

```text
核心问题；
新对象；
核心公式；
推导或证明；
边界；
与前后章节的衔接；
公式索引；
定义索引；
读者自检或思考题。
```

---

## 4. 章节写法：先问题，再对象，再公式

每个关键小节都应尽量采用：

```text
例子 / 问题
→ 暴露矛盾
→ 定义新对象
→ 给出公式
→ 解释公式
→ 回到例子
```

禁止直接从公式开始堆叠。

正确写法：

```text
先说明二维机器人为什么只看单步动作不够；
再定义动作块 A_t；
再给出 A_t=a_{t:t+H}；
最后解释它如何表达一段绕障碍动作意图。
```

错误写法：

```text
先列专家轨迹公式；
再列训练样本公式；
再列损失公式；
再列经验风险公式；
读者不知道哪个是本章主角。
```

---

## 5. 核心对象优先原则

每章必须先确定唯一主角。

这个主角可以是：

```text
执行分布；
DAgger 数据聚合；
动作块；
MSE 条件均值；
隐变量策略；
occupancy measure；
reward ambiguity；
GAIL 判别器；
动作去噪过程；
flow velocity field；
Transformer context；
world model。
```

所有公式、定义、证明、例子都必须服务这个主角。

禁止把章节写成“相关公式集合”。读者读完后必须能复述：

```text
本章新对象是什么；
为什么需要它；
它解决什么问题；
它的核心公式是什么；
它留下什么问题给下一章。
```

## 6. 公式管理总规则

### 6.1 全书公式目录

全书必须维护：

```text
全书公式目录.md
```

该文件是全书核心公式的唯一索引。

每当新增、重写或大幅修改章节时，必须检查：

```text
是否新增了全书级核心公式；
是否复用了已有公式但没有引用；
是否把辅助公式误当核心公式反复编号；
是否需要更新全书公式目录。
```

### 6.2 首次出现原则

一个公式第一次进入全书数学主线时，需要完整说明：

```text
公式解决什么问题；
公式中每个符号表示什么；
公式从哪些定义推出；
公式适用边界是什么；
它如何连接下一步主线。
```

### 6.3 后文复用原则

已经正式介绍过的公式，后续章节直接使用或引用，不再重新重点讲解、重新定义、重新编号或重复推导。

正确写法：

```text
沿用公式 (1.3) 的执行分布写法……
第5章已经说明 MSE 的最优点估计是条件均值，下面直接使用这个结论……
由公式 (6.4) 的隐变量边缘化形式可知……
```

错误写法：

```text
再次完整定义同一个公式；
再次逐字解释已解释过的符号；
给同一个数学对象换一个公式编号重新出现；
重复推导已经证明过的结论。
```

### 6.4 公式分级

全书公式分为三类。

```text
A 类：全书主线核心公式
B 类：章节支撑公式
C 类：推导中间式 / 例子公式
```

A 类进入《全书公式目录.md》。B 类可进入本章公式索引。C 类一般不进入全书公式目录，也不应密集编号。

一个公式是否是核心公式，至少满足以下条件之一：

```text
1. 定义一个后续会反复使用的数学对象；
2. 给出一个核心训练目标或优化目标；
3. 支撑一个关键命题；
4. 建立篇章之间的数学衔接；
5. 是后续方法的统一抽象形式。
```

### 6.5 每章核心公式数量

每章核心公式应少而准。

建议每章控制在：

```text
3–6 个核心公式
```

其余公式应降级为：

```text
正文说明；
推导框；
例子框；
附录提示；
公式索引中的辅助公式。
```

### 6.6 公式格式

公式格式统一参考《公式格式说明.md》。基本要求包括：

```text
禁止 \tag{}；
禁止 <div class="math">；
禁止 <span class="math">；
禁止 \operatorname；
公式块中不放中文说明；
重要公式使用“公式 (x.y)：公式名称 + 纯公式块”。
```

推荐格式：

```markdown
**公式 (x.y)：公式名称**

$$
...
$$
```

## 7. 定义管理规则

定义不是装饰。每个定义必须承担职责。

一个定义应该满足：

```text
后续章节会复用；
本章推导必须依赖；
能帮助读者区分相近对象；
能压住本章主线。
```

禁止为了形式统一而堆定义。

定义应采用：

```markdown
**定义 x.y：定义名称**

定义内容……
```

每章末尾应有“本章定义索引”，但定义索引不能替代正文中的解释。

---

## 8. 推导与证明规则

推导必须服务理解，不是展示公式技巧。

推荐使用“台阶式推导”：

```text
先写目标；
再写已知定义；
再做一步变形；
解释这一步为什么成立；
最后得到结论；
回到例子解释含义。
```

复杂推导应拆为：

```markdown
> 推导框：...
```

证明必须说明适用条件和边界。

例如：

```text
MSE 最优解是条件均值，前提是使用平方误差点估计。
固定方差高斯 NLL 与 MSE 等价，前提是方差固定。
单峰高斯不能充分表达强多峰分布，前提是多个模式相距较远。
```

---

## 9. 直觉框 / 推导框 / 边界框

全书统一使用三类框。

### 9.1 直觉框

用于解释公式在例子中表示什么。

```markdown
> **直觉框：标题**
>
> 内容……
```

### 9.2 推导框

用于放辅助推导，避免主线被中间步骤打断。

```markdown
> **推导框：标题**
>
> 内容……
```

### 9.3 边界框

用于说明结论何时成立、何时变弱。

```markdown
> **边界框：标题**
>
> 内容……
```

## 10. 统一例子规则

每一篇应尽量使用统一贯穿例子，不要每节换一个例子。

第一、二篇主例子：

```text
二维机器人从起点到目标，中间有障碍物。
可以绕左，也可以绕右。
同一状态下可能有多个合理动作模式。
```

第三篇可继续使用该例子解释 reward / occupancy / distribution matching。

第四篇可把例子扩展为：

```text
机器人需要输出一段连续动作；
动作可能是 chunk、去噪生成序列、或 flow 生成序列。
```

第五篇可把例子扩展为：

```text
策略不仅依赖当前状态，还依赖历史上下文、视觉观测、语言指令或任务条件。
```

第六篇可把例子扩展为：

```text
策略不仅要生成动作，还要预测动作后果。
```

其他工业例子，如插入、抓取、泊车、装配，可以作为旁注或边界说明，但不能频繁替换主例子。

## 11. 篇章职责

### 第一篇：模仿学习的基本范式

职责：建立模仿学习的第一性原理。

必须讲清楚：

```text
专家轨迹是什么；
策略是什么；
执行分布是什么；
BC 为什么只是专家分布上的动作拟合；
分布偏移为什么出现；
DAgger 为什么能修正训练分布。
```

第一篇的核心对象：

```text
τ, π(a|s), d_π(s), ρ_π(s,a), ρ_E, D(ρ_π,ρ_E), DAgger 数据聚合
```

### 第二篇：动作分布、轨迹损失与隐变量策略

职责：研究策略项本身如何表达动作。

必须讲清楚：

```text
动作不是孤立一步，因此需要动作块；
动作不一定只有一个标准答案，因此需要动作分布；
MSE 会学习条件均值；
多峰动作下条件均值可能不可行；
隐变量 z 可以表达动作模式；
CVAE 是训练隐变量策略的一种机制。
```

第二篇核心对象：

```text
a_t, A_t, D_chunk, π(A_t|c_t), f_θ(s), R(u|s), E[a|s], π(a|s), z, π(a|s,z), q_φ(z|s,a), p_θ(a|s,z), p_ψ(z|s)
```

### 第三篇：分布匹配与奖励视角

职责：从经典模仿学习角度解释“模仿专家行为”还可以被写成 occupancy matching、reward inference、adversarial learning。

必须讲清楚：

```text
IRL 不是普通监督学习；
reward ambiguity 为什么存在；
MaxEnt IRL 为什么引入概率轨迹；
GAIL 如何把 occupancy matching 变成对抗学习；
Offline IL 为什么受数据覆盖限制。
```

### 第四篇：现代机器人策略模型

职责：解释现代机器人策略如何从点估计升级为动作序列生成。

必须讲清楚：

```text
ACT 为什么预测 action chunk；
Diffusion Policy 为什么把动作看成逐步去噪生成；
Flow Matching 为什么学习连续速度场；
BC / ACT / Diffusion / Flow 的建模对象和训练目标差异。
```

已在第二篇介绍过的动作块 $A_t$、动作块策略 $\pi_\theta(A_t\mid c_t)$、概率策略 $\pi_\theta(a\mid s)$，第四篇直接使用，不再重新重点讲解。

### 第五篇：历史上下文与多模态条件策略

职责：解释策略条件从当前状态扩展到历史上下文、视觉、语言和任务条件。

必须讲清楚：

```text
为什么策略可以写成序列模型；
Decision Transformer 如何把轨迹当 token 序列；
Transformer Policy 如何用历史上下文预测动作；
VLA 如何统一视觉、语言与动作；
多模态条件不是炫技，而是扩展 c_t 的内容。
```

应直接沿用第二篇的 $c_t$ 和 $\pi_\theta(A_t\mid c_t)$ 视角。

### 第六篇：从动作模仿到世界预测

职责：解释为什么只学动作还不够，需要预测动作后果。

必须讲清楚：

```text
world model 预测什么；
latent dynamics 为什么不一定预测像素；
World Action Model 如何预测动作条件未来；
JEPA 式表示预测与重建式预测的区别；
世界预测如何进入计划、验证和安全边界。
```

## 12. 推荐阅读写法

每章推荐阅读不应只是列论文名，而要说明“重点看什么”。

推荐格式：

```markdown
## 推荐阅读：重点看什么

- **某方向资料**：重点看……，暂时不用卡在……
- **某论文 / 方法**：重点看它如何定义对象……
```

## 13. 配图规则

配图必须服务数学主线，不做装饰。

要求：

```text
SVG 优先；
图号与章节号一致；
图注说明图在本章中的作用；
每张图只解释一个核心关系；
不要让图中公式过多；
图片命名与正文引用一致。
```

每章配图清单必须包含：

```text
图号；
图名；
图要表达的核心关系；
是否已有文件；
是否需要新生成。
```

## 14. 章节结尾规则

每章结尾必须回答三件事：

```text
本章完成了哪个对象升级；
本章公式能让读者判断什么；
本章留下什么问题给下一章。
```

不能只写泛泛总结。

---

## 15. 禁止事项

全书改写时禁止：

1. 把章节写成公式清单。
2. 把章节写成论文综述。
3. 先使用符号，再解释符号。
4. 已介绍公式后文重复定义、重复编号、重复推导。
5. 每个相关公式都编号，导致主次不分。
6. 只有直觉，没有数学对象。
7. 只有公式，没有例子和解释。
8. 只有结论，没有证明或边界。
9. 每节频繁更换例子。
10. 把工程经验段落写得压过数学主线。
11. 出现作者自我说明、写作计划、修改记录等非正文内容。
12. 章节结尾只总结，不引出下一章。
13. 推荐阅读只列名字，不告诉读者重点看什么。
14. 旧编号、旧标题、旧交叉引用残留。
15. 公式格式违反《公式格式说明.md》。

## 16. 验收标准

每章改完后，必须通过以下检查。

### 16.1 主线检查

```text
本章唯一主角是什么？
本章对象从什么升级到什么？
本章和上一章如何连接？
本章给下一章留下什么问题？
```

### 16.2 公式检查

```text
本章核心公式是否不超过 3–6 个？
是否有已介绍公式被重复重点讲解？
是否更新了全书公式目录？
公式格式是否符合《公式格式说明.md》？
公式块中是否没有中文？
是否存在 \tag{}、<div class="math">、<span class="math">、\operatorname？
```

### 16.3 定义检查

```text
定义是否真的服务主线？
定义是否先于使用？
定义索引是否完整？
是否存在为了形式而堆定义？
```

### 16.4 读者体验检查

```text
普通工程师是否能知道本章公式解决什么问题？
是否有统一例子帮助理解？
复杂推导是否分层？
边界是否说明？
读完本章能判断什么是否明确？
```

### 16.5 仓库检查

```text
SUMMARY 链接是否正确？
章节目录是否正确？
数学主线文档是否同步？
全书公式目录是否同步？
图号、图注、图片路径是否一致？
旧计划、旧编号、重复文件是否清理？
```

## 17. 后续篇章修改执行顺序

每次修改一个篇章时，按以下顺序执行：

```text
1. 先读本文件《全书写作指导.md》；
2. 再读《全书公式目录.md》；
3. 再读该篇导读和章节；
4. 判断该篇的核心对象升级；
5. 删掉与图书正文无关的计划、说明、重复内容；
6. 压缩公式清单，确定核心公式；
7. 已介绍公式只引用，不重复讲；
8. 补齐定义索引、公式索引、思考题、配图清单；
9. 更新 SUMMARY 和全书公式目录；
10. 最后检查公式格式和链接。
```
